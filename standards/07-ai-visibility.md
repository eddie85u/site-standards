# 07 · AI visibility
**Applies to:** every site.

## Why
More buyers ask ChatGPT, Claude, Perplexity, Gemini or Copilot instead of searching. Those assistants can only recommend a business whose pages they are allowed to fetch and can read quickly. Many sites block them by accident, through a setting at their hosting or security provider, or hide their text behind code that the assistants do not run, and never find out. This standard makes the site readable; standard 03 makes it the one they pick.

How common the accidental block is: since July 2025, new sites on Cloudflare block AI crawlers by default, and more than a million owners had already switched on the one-click block ([Cloudflare, 2025](https://www.cloudflare.com/press/press-releases/2025/cloudflare-just-changed-how-ai-crawlers-scrape-the-internet-at-large/)). We found one ourselves: a site whose robots.txt welcomed every AI assistant while its Cloudflare setting turned them all away.

## Rules
1. **Decide the policy per site and write it in the site's AGENTS.md.** For a business that wants to be found: allow search crawlers, AI answer and search bots, and AI training crawlers; block pure scrapers.
   *Why:* the default on some CDNs and templates is to block AI bots "for security", which quietly removes you from answers.
2. **robots.txt names the bots that matter** (template: `templates/robots.txt`):

   | Company | Training | Search / answers | User-triggered fetch |
   |---|---|---|---|
   | OpenAI | `GPTBot` | `OAI-SearchBot` | `ChatGPT-User` |
   | Anthropic | `ClaudeBot` | `Claude-SearchBot` | `Claude-User` |
   | Perplexity | | `PerplexityBot` | `Perplexity-User` |
   | Google | `Google-Extended` (a control token, not a crawler) | `Googlebot` | `Google-Agent` and other user-triggered fetchers (ignore robots.txt) |
   | Apple | `Applebot-Extended` (control token) | `Applebot` | |
   | Microsoft | | `Bingbot` (also feeds Copilot) | |
   | Meta | `meta-externalagent` | | `meta-externalfetcher` |
   | Amazon | `Amazonbot` | | |
   | Mistral | | | `MistralAI-User` |
   | DuckDuckGo | | `DuckAssistBot` | |
   | Common Crawl | `CCBot` | | |

   Current names: [OpenAI](https://platform.openai.com/docs/bots), [Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler), [Perplexity](https://docs.perplexity.ai/guides/bots), [Google](https://developers.google.com/crawling/docs/crawlers-fetchers/google-user-triggered-fetchers).

   *Why:* each column is a different decision. `OAI-SearchBot` decides whether ChatGPT search can cite you; `GPTBot` only covers training. `Google-Extended` has no effect on Search or AI Overviews. Blocking the wrong one costs citations and gains nothing.
3. **The CDN's bot setting must agree with robots.txt.** On Cloudflare, check *Security → Settings* and *AI Crawl Control*.
   *Why:* a zone-level block answers 403 no matter what robots.txt says, and robots.txt looks fine in the repo.
4. **Content-Signal** under `User-agent: *` (Cloudflare's Content Signals Policy): `Content-Signal: search=yes, ai-input=yes, ai-train=yes`, adjusted to the policy.
   *Why:* it states the policy in a form the newer crawlers read, separately for search, answers and training.
5. **`/llms.txt`** following llmstxt.org (template: `templates/llms.txt`): one H1 with the brand, a `>` summary, short factual paragraphs (what, for whom, where, how to buy, what you don't do), `##` sections of links with one-line descriptions, and an `## Optional` section.
   Bilingual sites: `/llms.txt` in the main language, with a `##` section per language that lists that language's pages. When the second language lives in its own folder (`/en/`), add `/en/llms.txt` written in that language for those pages.

   *Why:* agents and some assistants fetch it to understand a site in one request. It is cheap and harmless. Be honest about its limits: Google says Search does not use llms.txt ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)), so it never replaces readable pages. Since v2 (August 2026), a file in a folder covers the pages under it and agents use the most specific file ([llmstxt.org](https://llmstxt.org/)), so a folder file answers in the visitor's language while the root file still finds both.
6. **`/llms-full.txt` and Markdown copies** (optional, once content is stable): generated by a script from the HTML so they never drift.
   On Cloudflare Pro or above, *AI Crawl Control → Markdown for Agents* does this at the edge instead: a request with `Accept: text/markdown` gets the page converted to Markdown (HTML up to 2 MB, with an `x-markdown-tokens` header), and browsers still get HTML. Free plans had a waitlist in 2026. Some coding agents already send that header, Claude Code and OpenCode among them ([Cloudflare](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/)).
   *Why:* a hand-kept copy goes stale and then contradicts the site.
7. **Text is in the HTML.** Real content in the delivered markup, not injected only by scripts.
   *Why:* assistants that fetch a page for a user usually do not run JavaScript. A page that renders from JSON shows them a skeleton.
8. **Comparison-ready content and one page per thing people search for:** see standard 03.

## How to build it
1. Copy `templates/robots.txt` and `templates/llms.txt`; fill the placeholders from the site's real copy.
2. Check the Cloudflare zone bot settings match.
3. If the site renders text from JSON with JavaScript, pre-render it into the HTML with the same markup function the browser uses, and give the script a `--check` mode that fails in CI when the HTML is out of date with the data. Two sites fixed it this way without changing how the pages look. Generating llms-full.txt from the data files helps but does not replace it: an assistant fetches the page the buyer asked about.

## Check
```sh
curl -s https://example.com/robots.txt
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" https://example.com/llms.txt     # 200 text/plain or text/markdown
curl -s -o /dev/null -w "%{http_code}\n" -A "GPTBot/1.2" https://example.com/              # 200, not 403
curl -s -o /dev/null -w "%{http_code}\n" -A "ClaudeBot/1.0" https://example.com/           # 200
curl -s -o /dev/null -w "%{http_code}\n" -A "PerplexityBot/1.0" https://example.com/       # 200
curl -s https://example.com/some-page | grep -c "<p"                                       # real paragraphs without JS
# The selling text without JS: strip scripts and styles, then look for what buyers ask about
curl -s https://example.com/ | perl -0pe 's/<(script|style)\b.*?<\/\1>//gis; s/<[^>]+>/ /g' | grep -o '\$[0-9][0-9,]*' | sort -u   # every published price; none means they need JS
```
- The no-JavaScript text holds the prices, the services and the FAQ answers, not just a hero and a footer. A paragraph count passes on a page whose selling sections are empty containers filled by a script; read the stripped text or look for the prices themselves. Change the price pattern to the site's currency (`COP`, `€`).
- Run it on one page of each template (home, a service page, the FAQ, reviews). One site pre-rendered its service pages while its FAQ page delivered none of its questions.
- Text inside fade-in ("reveal") elements is visible without JavaScript: a `<noscript>` style or a class the script adds, never `opacity: 0` in the base CSS alone.
- Cloudflare → AI Crawl Control: the bots you allow show 200s, not 403s.
- Markdown for Agents, where it is on: `curl -s -o /dev/null -w "%{content_type}\n" -H "Accept: text/markdown" https://example.com/` prints `text/markdown`; without the header it prints `text/html`.
- Ask two or three assistants "What does <brand> do and who is it for?" and compare the answer with the site.

## Avoid
- **Outdated or invented user agents.** `Claude-Web` and `anthropic-ai` are retired; `CopilotBot`, `BraveBot`, `NeevaBot`, `PhindBot` are not real crawlers. Compare robots.txt against the table above.
- **Reporting "AI blocked" from the wrong bot,** for example treating a `GPTBot` block as a ChatGPT search block.
- **`Crawl-delay`**: Google ignores it, others slow down for no benefit on a small site.
- **`#` comment lines at the top of llms.txt.** A line starting with `# ` is a heading, so a comment header creates several H1s. `grep -c "^# " llms.txt` must print 1.
- Prices, guarantees or claims in llms.txt that the visible site does not make, or that go stale.
- Blocking AI bots at the CDN "for security" and forgetting it.
- Trusting the repo copy of robots.txt: if Cloudflare's managed robots.txt is on, Cloudflare adds its own block to the top of the live file. Always read the live one.
- Repeating prices in llms.txt on sites with rules about where prices may appear: link to the pages that show them instead, so the file never contradicts the site.
